1. 项目概览

Lemon Music 是一个面向飞牛 NAS（fnOS）与自托管环境的 Web 音乐管理工具，在浏览器中完成「找歌 → 试听 → 下载 → 整理」全流程：

维度说明
定位NAS 个人音乐整理工具，兼容落雪音乐（LX Music）自定义音源脚本
核心能力多平台搜索（酷我/酷狗/QQ/网易云/咪咕）、发现页（歌单/榜单/新歌/新碟）、试听播放、批量下载、本地标签编辑（MP3/FLAC/WAV/APE）、音乐库管理、查重备份、多用户与音源健康度
部署形态飞牛 FPK 原生应用（不依赖 Docker），默认端口 7983；亦可本地开发运行
音源体系两套机制并存：内置 musicSdk.js 直连平台接口 + 用户导入的落雪/澜音脚本沙箱运行时
仓库github.com/jia070310/lemon-muisc

4. 总体架构

前后端同仓部署，开发期由 Vite 代理，生产期由 Express 托管静态产物。整体数据流如下：

进程与端口

浏览器 ──► Vite dev (5174) ──代理──► Express (7983)
                     │                      │
                     │  /api/*  HTTP+JWT     │
                     ├──────────────────────►├──► better-sqlite3 (config/lx-music.db)
                     │                      ├──► 音源沙箱 (vm) ──► 平台 API
                     │  /ws WebSocket        ├──► 内置 SDK (needle) ──► 平台 API
                     └──────────────────────►├──► 下载队列 (内存 Map + 任务表)
                                             └──► 本地文件系统（音乐库/下载/标签）

请求处理链

浏览器 fetch / WS
→
api.js 客户端（限流6/超时/401跳转）
→
Express 中间件（CORS / JWT）
→
routes/* 路由模块
→
utils/* 业务逻辑

认证体系

  • POST /api/auth/login 签发会话 → sessions 表；前端存 localStorage["lemon-auth-token"]
  • 除 /auth/*、/health 外，所有 /api/* 均经 requireAuth 中间件
  • WebSocket 以 URL 参数 ?token= 校验（validateWsToken）
  • 音频流 URL 由 appendStreamToken 追加短期 token（/api/play/、/api/tag/cover）
  • 角色：admin（用户/路径管理）与 user（普通用户，仍可管理自己的音源启用与歌单）

6. 后端设计

服务入口 server/index.js

启动流程：初始化 SQLite → 迁移文件路径 → 刷新音源元数据 → 挂载 /api → 托管前端静态产物（SPA fallback）→ 启动 WebSocket → 恢复各用户激活音源（跳过故障音源）→ 初始化下载队列 → 内存守卫 → 遥测。

优雅停机：SIGINT/SIGTERM 时停止遥测、关闭 WS 与 HTTP。端口占用（EADDRINUSE）给出友好提示。

音源沙箱（sourceManager.js）

支持两种音源规范，在 vm 沙箱中加载：

  • LX Music 落雪规范：暴露 lx 全局（send/on/request/utils），utils 提供 crypto（AES/RSA/MD5）、buffer、zlib 等受限能力；request 经服务端代理转发
  • 澜音 cerumusic 规范：createCerumusicApi() 创建兼容对象并归一化为同名 source

支持平台：kw（酷我）/ kg（酷狗）/ tx（QQ音乐）/ wy（网易云）/ mg（咪咕）；支持动作：musicUrl / lyric / pic；音质档：128k / 320k / flac / flac24bit / hires / atmos / atmos_plus / master。

安全设计：沙箱内 console 置空、require 白名单化、初始化 20s 超时、同 id 先卸后装避免重复沙箱；故障判定区分临时网络错误（不封源）与永久故障（停用并广播 source.fault）。

8. 核心机制

8.1 下载流水线

/download/add（多任务）
→
质量档位校验（无此音质→降档确认）
→
同名文件检测（询问/跳过/覆盖）
→
取链（同音质 3 次尝试 + 换源兜底）
→
下载 + 试听时长校验（短片段自动取消）
→
写入标签/封面/歌词

细节：并发上限可配；中断可续传（await_exist / await_source 等确认态）；任务状态经 download:added / download:cleared 事件推送；结束写入 library 索引并广播 library:changed。

「真 FLAC」校验：无损档位会检查 Content-Type 与文件头（assertLosslessContentType / assertLosslessFile），防止"假无损"；试听时长明显短于曲目时长则取消并归类可单独重试。

8.2 播放链路与换源

POST /api/play/url → 构建 musicInfo → 播放 URL 缓存（LRU，playUrlCache）→ 音源请求（playUrlLimiter 8 并发、25s 超时）→ 校验 URL → 包装为代理或直链 + 流 token。失败时返回 409 SOURCE_FALLBACK_REQUIRED，前端据此弹出「换平台/换音源」选择。

音频代理

  • GET /api/play/local — 本地文件 Range 流式播放（白名单目录校验）
  • GET /api/play/local-ape — APE 经 ffmpeg 转码为 WAV 缓存后流式输出
  • GET /api/play/proxy — 远程音频反代（带平台 Referer、Range 透传、8 路上限、SSRF 防护：拒绝内网/局域网地址）

8.3 试听短片段自动恢复

播放链异常时：同平台换音源 → 其它平台搜同名曲 → 完整播放后再继续；「无法播放该音频格式」误报大幅减少。

8.4 标签系统

meta.js 按扩展名分发：MP3 用 node-id3（ID3v2），FLAC 用 music-metadata 写 Vorbis Comment；WAV / APE 为自实现写入器（wavTag.js / apeTag.js），保存更稳、封面不误清。标签匹配：matchByFilename / matchByArtistTitle 调用音源 pic/lyric 与搜索，支持手动检测标黄一键采用、按文件名批量重设、并发 1–6 路可调。

8.5 音乐库与查重

定时/手动扫描 → 写入 library_index（mtime 增量）→ 内存缓存（libraryCache）→ 智能歌单（最新添加/最近播放/收藏）。查重按「标题+歌手」聚合，同组至少保留一份，可复制路径或删除磁盘文件。

8.6 内存守卫与遥测

memoryGuard.js 定时监控进程内存；telemetry.js 匿名用量统计（可关闭，fpk 提供 no-telemetry 构建）。

8.7 飞牛 FPK 打包

scripts/build-fpk.ps1 生成 fpk/lemon-music-<ver>-<arch>.fpk；fpk/manifest 声明依赖 nodejs_v22、端口 7983、服务脚本（cmd/ 下的 install/upgrade/uninstall 回调）。

10. WebSocket 事件

连接：ws://host/ws?token=<jwt>，校验失败以 4401 关闭。消息格式 { type, data }。服务端广播时支持按用户过滤（userId）。

事件范围说明
download:added / download:cleared用户级下载任务新增 / 队列清空，驱动进度条
library:changed / library:removed全员音乐库变更（新下载入库 / 文件移除）
library:scan-progress / library:scan-complete全员扫描进度与完成
library:user-data-changed用户级个人歌单/收藏变更
source.fault用户级音源故障，前端提示修复/停用

客户端：指数退避重连（1s→15s）、弱网（online/visibilitychange）自动恢复、断线静默。
